## Summary

Issue #552 asks whether the fixed corpus's 18 `MISS` rows and 168 metamorphic
critical failures (`openai-token` 81, `cloudflare-token` 27, `docker-token`
27, `slack-token` 27, `generic-token` 6) share one root cause, and to fix
whichever families that hypothesis actually explains.

**The shared-root-cause hypothesis is confirmed for `openai-token`,
`cloudflare-token`, `docker-token`, and `slack-token` (162 of 168
failures) — but its direction is the opposite of the issue's framing.** These
are not shapes the detector fails to cover; they are shapes four
already-accepted, evidence-reviewed contract freezes deliberately excluded.
No product code change is warranted for these four families. This is not a
new finding: it is the same disposition [`evidence/367`](../367/README.md),
[`evidence/376`](../376/README.md), and issue #402's review already reached,
independently re-confirmed for each family in
[`evidence/405`](../405/README.md) (OpenAI), [`evidence/406`](../406/README.md)
(Slack), [`evidence/407`](../407/README.md) (Docker), and
[`evidence/408`](../408/README.md) (Cloudflare) three days before #552 was
filed. This document adds the piece those four single-fixture reviews did not
need to cover: why the failure count *scales* the way #552 observes, and it is
the first to give a full account of `generic-token`'s 6 failures.

**`generic-token`'s 6 metamorphic failures (of the 168) are a genuine,
independent, now-fixed product defect**, unrelated to the four provider
contract freezes above. See "The `generic-token` defect" below.

## Why the four provider families' misses are intended, not a gap

Each family's `detector-coverage--<family>-shape-N-{bare,quoted,unicode-crlf}`
fixture is generated by `redact-secret-benchmarks`'
`fixtures/generated/detector-coverage.mjs`, whose `families` table builds
every shape from one formula: a documented prefix plus `synthetic(seed,
length)`, a deterministic SHA-256-derived run of the *default* alphabet
(`[A-Za-z0-9]`, no punctuation), with a single shared length per family. That
formula was authored against beta.3-era permissive rules ("recognized prefix
plus an N-byte minimum") — the file's own header comment says as much
("Authored against the beta.3 format contracts, never scanner output"). Four
later, independently reviewed decisions replaced those permissive rules with
structural grammars the formula's flat random body cannot satisfy by
construction:

| family | `shape-1` fixture (reproduced below) | frozen contract | why it fails |
| --- | --- | --- | --- |
| `openai-token` | `sk-` + 48 random alnum bytes (shapes 2/3: `sk-proj-`/`sk-svcacct-` + 48) | `<segment>T3BlbkFJ<segment>`, exact segment lengths (#368) | contains no `T3BlbkFJ` marker at all |
| `docker-token` | `dckr_pat_` + 32 random alnum bytes | `dckr_pat_` + exactly 27 bytes; `dckr_oat_` + exactly 32 (#370) | wrong length for `dckr_pat_` (shape-2, `dckr_oat_`, happens to match 32 and is not in #552's count) |
| `slack-token` | `xoxb-` + 48 random alnum bytes, no dashes | `xoxb-<10-13 digits>-<10-13 digits>-<18+ alnum>` (#371) | no `-`-sectioned digit groups at all |
| `cloudflare-token` | `cfut_` + 40 random alnum bytes | `cfut_` + 40-byte body + exactly 8-byte lowercase-hex checksum (#367) | missing checksum tail entirely |

Reproduced independently for this document (not taken from prior citations)
by replicating `detector-coverage.mjs`'s `synthetic()` generator:

```
$ python3 - <<'EOF'

        h = hashlib.sha256(f"secret-benchmark:never-issued:v2:{label}:{block}".encode()).digest()
        for b in h: value += chars[b % len(chars)]
        block += 1
    return value[:length]
for detector, prefix, length in [
    ("openai-token", "sk-", 48), ("openai-token", "sk-proj-", 48),

    ("docker-token", "dckr_pat_", 32), ("docker-token", "dckr_oat_", 32),
    ("cloudflare-token", "cfut_", 40),
]:
    body = synthetic(f"detector-coverage:{detector}:{prefix}", length)
    print(detector, prefix, "T3BlbkFJ" in body if detector == "openai-token" else "-" in body if detector == "slack-token" else len(body))
```

`docker-token`'s `dckr_pat_` body is 32 bytes against a required 27 (too
long); `dckr_oat_`'s is 32 against a required 32 (matches — which is why only
`docker-token-shape-1`, not `shape-2`, is in #552's or #407's count). Every
other row above shows the structural feature (marker, dash-sectioning,
checksum) the frozen grammar requires is simply absent from the fixture, not
present-but-malformed.

Each detector's own tests already assert the rejection this table predicts —
`rejects_the_marker_less_broad_shapes_the_previous_rule_accepted`
(`crates/secret-scan-core/src/detectors/openai.rs:325`),
`a_bot_section_grammar_failure_never_falls_back_to_the_interim_guard`
(`crates/secret-scan-core/src/detectors/slack.rs:402`),
`docker_distinguishes_unicode_crlf_twins_from_their_paired_positives`
(`crates/secret-scan-core/src/detectors/additional_providers.rs:1051`), and
`rejects_a_body_one_byte_short_of_the_documented_length` /
`rejects_a_non_hex_checksum` (`crates/secret-scan-core/src/detectors/cloudflare.rs:188,229`)
— line numbers verified against this branch's current tree, not copied from
the prior citing documents' dates. The full workspace suite (`cargo test
--workspace`, 1231 passed, run 2026-09-21 on this branch) confirms none of
these four detectors' behavior has changed.

## Why the metamorphic count scales the way #552 observes

`redact-secret-benchmarks`' `metamorphic` method applies ~27 envelope
transforms (`context.*`, `encoding.*`, etc.) to each canonical case and
asserts both `present-within-envelope` on every transformed variant and
`same-detection` against the untransformed baseline. A metamorphic case built
from a `detector-coverage` shape that is already undetected at its own
`canonical` (identity) variant fails **every** transformed variant for the
same reason the baseline does — it is not that the envelope transform breaks
robustness, it is that there was never a detection to preserve. That
mechanically multiplies each family's one structural miss by its envelope
count: `openai-token` carries 3 broken shapes (legacy, `proj`, `svcacct`) and
scores roughly 3× the failures of `cloudflare-token`/`docker-token`/
`slack-token`, which each carry 1 — exactly the scaling #552 itself flagged
("openai has 3 missed shapes and ~3× the failures of the others"). This
resolves the open half of #552's hypothesis: the single shared root cause is
not a detection-robustness defect at all, it is one stale fixture-generation
formula, replicated once per envelope transform.

## The `generic-token` defect (confirmed, independent, fixed in this PR)

`generic-token`'s 6 failures are unrelated to the four families above:
`generic-token` is `redact-secret-benchmarks`' own T3 contextual detector
target, built from `quoted("<field>=", <literal>)` (a well-formed
`field="value"` assignment), not a provider shape. Isolating the failing
assertions from a locally captured `eval:classify` run
(`redact-secret-benchmarks`, `results-output/evaluation.json`,
`startedAt: 2026-09-18T03:36:06.308Z`) narrows them to exactly three fixtures
under one operator:

```
detector-coverage--generic-token-api-key-bare--metamorphic       context.markdown: present-within-envelope FAIL, same-detection FAIL
detector-coverage--generic-token-password-bare--metamorphic      context.markdown: present-within-envelope FAIL, same-detection FAIL
detector-coverage--generic-token-client-secret-bare--metamorphic context.markdown: present-within-envelope FAIL, same-detection FAIL
```

Three fixtures × two assertion types = 6, matching #552's count exactly.
`benchmarks/operators/context.ts`'s `context.markdown` operator wraps the
whole canonical fixture in a matching pair of backticks with no other change
(`` `api_key="<value>"` ``) — Markdown inline code.

**Root cause:** `crates/secret-scan-core/src/detectors/generic_token.rs`'s
`is_prefix_boundary_char` (the set of characters allowed immediately before a
recognized assignment name) and `is_quoted_value_boundary` (the set allowed
immediately after a quoted value's closing quote) did not include a backtick.
An opening backtick sits directly against the key name with no whitespace or
other separator, and the matching closing backtick sits directly against the
value's closing quote the same way — both already-accepted precedents for
this exact shape (a bare quote is accepted as a boundary for the identical
reason, `value="api_key="TOKEN""`, issue #294). Without the backtick
alternative, `assignment_candidates` never recognized the name at all: the
whole assignment was invisible, not merely mis-spanned.

**Fix:** add `` '`' `` to both boundary character sets
(`crates/secret-scan-core/src/detectors/generic_token.rs`). `is_unquoted_value_boundary`
is deliberately left unchanged: an existing test,
`a_value_only_starting_with_an_interpolation_delimiter_is_still_detected`,
depends on an *unclosed* leading backtick (no matching close) still being
swallowed as a literal unquoted-value byte via the existing
`delimited_reference_value` fallback (issue #266/#279's documented tradeoff);
widening `is_unquoted_value_boundary` the same way regressed that case by
terminating the value at zero length before it could be captured. The fix is
scoped to the two boundary functions that actually gate the failing
(quoted-value) shape.

**Verification:**

```
cargo test -p redact-secret generic_token
# 81 passed, 977 filtered out (20 suites) — includes the new
# a_high_signal_assignment_wrapped_in_markdown_inline_code_is_still_detected
cargo test -p redact-secret
# 1070 passed (21 suites)
cargo test --workspace
# 1231 passed (28 suites) — no regression anywhere else in the workspace
```

A permanent synthetic regression fixture,
`regression-generic-token-markdown-inline-code-boundary`, is added to
`conformance/fixtures/synchronous-corpus.json` (tier `regression`) per
[`convention-synthetic-secret-regressions`](../../../../conventions/synthetic-secret-regressions.md)
and [`decision-govern-benchmark-regression-promotion`](../../../decisions/2026-09-18-govern-benchmark-regression-promotion.md).
`docs/coverage/coverage-declarations.json` and
`docs/coverage/inventory-report.json` are regenerated accordingly and
`npm run coverage:check` passes.

No `conformance/benchmark-regressions.json` entry is added: that manifest
links a `benchmarkRecordId` from a promoted `redact-secret-benchmarks`
`known-gaps.json` record, and this defect was found by directly triaging a
local evaluation run rather than through that lifecycle — no such record
exists yet to cite. Filing it (`observed` → `reviewed` → `promoted`) is
benchmarks-side follow-up work, the same gap issue #548's own comment already
flagged for #551/#552/#553's governance records
(`redact-secret/redact-secret-benchmarks#66`).

## Acceptance criteria disposition

- **`metamorphic.criticalFailures` is 0 across all 42 families** — not
  achievable from this repository alone. 162 of 168 (`openai-token`,
  `cloudflare-token`, `docker-token`, `slack-token`) require regenerating
  `redact-secret-benchmarks`' `fixtures/generated/detector-coverage.mjs` shape
  formula to match the four frozen contracts; that is benchmarks-repo work,
  out of this repository's boundary (`AGENTS.md`'s security-boundary and
  change-rules sections). The remaining 6 (`generic-token`) are fixed by this
  PR.
- **The 18 `MISS` rows are 0** — same disposition and same dependency on the
  benchmarks-side fixture regeneration; no redact-secret code change closes
  this.
- **The root-cause finding is recorded, shared or independent, with
  evidence** — done, this document, extending and cross-referencing
  `evidence/367`, `evidence/376`, `evidence/402`, `evidence/405`–`408`.
- **No new false alarms: `falseAlarmRate` does not rise in any group** —
  verified by the full workspace suite (1231 passed) and the targeted
  `generic-token` suite (81 passed); the fix only widens two boundary
  character sets that already accept a bare quote for the identical
  no-separator reason, and `is_unquoted_value_boundary`'s existing
  interpolation-delimiter fallback is left untouched.
- **Shapes added at their honest tier; T2 shapes stay T2** — no shapes are
  added by this PR; `openai-token`'s and `docker-token`'s existing T2
  classification is unaffected.

## What this document does not claim

- It does not reopen or dispute the four families' frozen contracts; four
  independent, evidence-reviewed decisions (#367, #368, #370, #371/#512) and
  five independent reviews (#367, #376, #402, #405–408) already establish
  that these misses are the accepted cost of narrowing away real false
  positives.
- It does not perform the benchmarks-side fixture regeneration or the
  `known-gaps.json` promotion lifecycle; those require changes in
  `redact-secret-benchmarks`, a separate repository and a separate PR.
- It does not assert `generic-token`'s markdown-boundary defect is the only
  possible robustness gap in that detector; it reports the specific,
  reproduced defect behind #552's stated 6 failures and this PR's fix for it.
