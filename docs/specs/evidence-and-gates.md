# Evidence and gates

Rules governing CI gates, evaluation protocol, and how evidence (SAST, benchmarks, twin fixtures, support-matrix drift) blocks or unblocks a release.

> Generated for [issue #597](https://github.com/redact-secret/redact-secret/issues/597) (DS6a). Each rule
> below states current behavior in the present tense and links the ADR
> (`docs/decisions/`) that decided it. An ADR records why and when; this file
> records what is true now. Per
> [`decision-decide-artifact-taxonomy-spec-routing-and-evidence-placement`](../decisions/2026-09-22-decide-artifact-taxonomy-spec-routing-and-evidence-placement.md),
> a decision that applies an existing policy to one more provider family or
> one more instance is a row here plus its supporting evidence, not a new
> ADR.

## Rules

| Rule | Governing ADR |
| --- | --- |
| OpenGrep is the one SAST tool, run by exactly one command (`python3 scripts/run-sast.py`). The binary, its Sigstore signing identity, and the vendored ruleset revision are pinned in `sast/opengrep.lock.json`; install fails closed on a SHA-256 or `cosign verify-blob` mismatch, and the scan fails closed if the vendored rules' digest drifts. Bumping the tool or rules is a re-pin that re-triages every new finding. | [Pin OpenGrep and establish a reviewed SAST baseline](../decisions/2026-09-10-pin-opengrep-and-establish-a-reviewed-sast-baseline.md) |
| Every OpenGrep finding and scan error must be dispositioned in `sast/baseline.json` as `blocking`, `false_positive`, or `hardening`; an unclassified finding, a `blocking` one, or an unacknowledged scan error fails the scan. Finding ids derive from `(rule_id, path, start_line, end_line)`, so a line shift re-baselines. | [Pin OpenGrep and establish a reviewed SAST baseline](../decisions/2026-09-10-pin-opengrep-and-establish-a-reviewed-sast-baseline.md) |
| `.github/workflows/sast.yml` runs that command on every pull request and push to `main`, and passes or fails on its exit code alone, with least-privilege permissions, commit-pinned actions, and a bounded timeout. SARIF upload to code scanning is best-effort (`continue-on-error`), and syncing `false_positive`/`hardening` suppressions into alert state runs on `main` only; neither can change the gate's outcome. Making the check required in branch protection is an administrator action outside source. | [Pin OpenGrep and establish a reviewed SAST baseline](../decisions/2026-09-10-pin-opengrep-and-establish-a-reviewed-sast-baseline.md) (folded: `decision-enforce-opengrep-in-ci-as-a-required-gate`) |
| Every binding is evaluated against the same cross-language protocol before a behavior change is accepted. | [Define the cross-language evaluation protocol](../decisions/2026-09-12-define-cross-language-evaluation-protocol.md) |
| JavaScript performance is measured by an external harness, not by in-repo microbenchmarks alone. | [Measure JavaScript performance externally](../decisions/2026-09-12-measure-javascript-performance-externally.md) |
| A beta.5-class release is gated on measured precision gains plus preservation of existing true positives. | [Gate beta.5 on precision gains and positive preservation](../decisions/2026-09-18-gate-beta5-on-precision-gains-and-positive-preservation.md) |
| A regression found by `redact-secret-benchmarks` is promoted into a product fix through a defined lifecycle, not fixed ad hoc from a single benchmark run. | [Govern benchmark-originated product regressions](../decisions/2026-09-18-govern-benchmark-regression-promotion.md) |
| A benign twin fixture that looks like a real credential is rewritten to be unmistakably synthetic, never a plausible real secret. | [Resolve real-looking twin fixtures as unmistakably synthetic](../decisions/2026-09-18-resolve-real-looking-twin-fixtures-as-unmistakably-synthetic.md) |
| `benchmarks/pin-source.json` names the exact immutable `redact-secret-benchmarks` commit whose `benchmarks/pin-manifest.json` is vendored byte-for-byte. Development checks require that commit to be on benchmarks `develop`; the Release workflow requires it on benchmarks `main`. `benchmarks/support-matrix-schema.json` is a byte-for-byte copy of `schemas/support-matrix-v1.json` at the immutable benchmark commit whose evidence contract this repository consumes (currently [`cfaeac4d83a4c98cffd77328d3416eb920a7d25b`](https://github.com/redact-secret/redact-secret-benchmarks/blob/cfaeac4d83a4c98cffd77328d3416eb920a7d25b/schemas/support-matrix-v1.json), the beta.8 documented/empirical qualification contract). `benchmarks/README.md` lists every source and check. `npm run benchmark-pins:check` (in `npm run ci`, offline) reconciles the regression ledger against the manifest. The live `benchmark-pin-drift` job verifies ancestry and byte identity at immutable refs. Re-pinning requires `npm run benchmark-pins:sync -- --ref <40-sha>`; advancing either immutable source is explicit. A closed ledger record keeps the corpus hash it measured and is anchored by its `benchmarkCommit` (#427, #605, #637, #725). | [Govern benchmark-originated product regressions](../decisions/2026-09-18-govern-benchmark-regression-promotion.md) |
| The support matrix reaches this repository only as the pinned, committed `benchmarks/support-matrix.json` (plus its vendored schema), copied from a `redact-secret-benchmarks` run; no status is re-derived or hand-edited here, and nothing fetches it over the network. Support status, evidence tier, evidence basis, and qualification profile remain separate fields. A T1 family can qualify through the `documented` profile (basis `provider-documented`) and a T2 family through the `empirical` profile (basis `independently-corroborated` or `empirically-observed`, the two routes of redact-secret-benchmarks' [`decision-qualify-empirical-stable-by-corroboration`](https://github.com/redact-secret/redact-secret-benchmarks/blob/cfaeac4d83a4c98cffd77328d3416eb920a7d25b/docs/decisions/2026-09-24-qualify-empirical-stable-by-corroboration.md)); qualification never rewrites evidence provenance. `docs/support-matrix.md`, the README support section, and the release-note fragment (`--release-note`) are generated from that pin by `scripts/generate-support-matrix-docs.py`, and `npm run support-matrix:check` fails CI if they drift from it. Whether the matrix pin is current against benchmarks `main` is not checked. | [Gate release qualification on support-matrix drift, with recorded acknowledgement to override](../decisions/2026-09-21-gate-releases-on-support-matrix-drift.md) (folded: `decision-project-support-matrix-into-docs-and-release-notes`) |
| Release qualification diffs the pinned matrix against the previous release tag's copy (`scripts/check-support-matrix-drift.py`, offline). A family leaving `stable` fails unless `benchmarks/support-matrix-drift-acknowledgements.json` holds an entry fingerprinted on `family\|baselineStatus\|candidateStatus\|reason`; improvements and new families never block. Evidence-provenance drift under an unchanged status only warns; the compatibility record key remains `staleProviderProvenance`, but its before/after bundles cover tier, basis, qualification profile, provider source, corroboration, empirical evidence, fixture profile, and detector metadata. The drift record is written before the check fails and embedded in the release manifest as `support_matrix_drift`; no previous tag records `{}` and passes. A dirty candidate is rejected unless `--allow-dirty-candidate`. | [Gate release qualification on support-matrix drift, with recorded acknowledgement to override](../decisions/2026-09-21-gate-releases-on-support-matrix-drift.md) |
| Every committed document or generated file has exactly one taxonomy kind (live contract, generated, final evidence, iterative log, settled-record detail, or release record), which fixes where it lives. | [Decide the artifact taxonomy, spec routing, and evidence placement](../decisions/2026-09-22-decide-artifact-taxonomy-spec-routing-and-evidence-placement.md) |
| Performance results, RC acceptance criteria, and pass/fail judgement live in `redact-secret-benchmarks`, not committed in this repository. | [Move performance results, criteria, and judgement to redact-secret-benchmarks](../decisions/2026-09-22-move-performance-results-criteria-and-judgement-to-benchmarks.md) |
| A link into another repository, `https://github.com/redact-secret/<repo>/blob/<ref>/<path>`, must resolve. **Policy:** a citation of a past state uses a 40-hex pinned permalink (it cannot break unless history is rewritten); a pointer to living documentation uses `main`; a branch ref is never used, and a release tag is accepted. `npm run cross-repo-links:check` (`scripts/check-cross-repository-links.py`) verifies resolvability, not intent: a pinned ref needs its commit and path, `main` needs the path on `main` today (this repository from the working tree, the other through `gh api`). It needs network access, so it runs as the `cross-repository-links` CI job and never in the offline `npm run ci`; its unit tests (`npm run cross-repo-links:test`) do run there. The wiki has the largest exposure and no CI of its own, so it is covered by the scheduled `Wiki links` workflow (weekly, `.github/workflows/wiki-links.yml`) rather than left to manual sweeps; a broken wiki link fails that run (#690). | [Decide artifact taxonomy, spec routing, and evidence placement](../decisions/2026-09-22-decide-artifact-taxonomy-spec-routing-and-evidence-placement.md) |
