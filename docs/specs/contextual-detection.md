# Contextual detection

Rules governing how a contextual assignment (`name = value`) is parsed, scoped, and excluded from generic-token and related context-driven detectors.

> Generated for [issue #597](https://github.com/redact-secret/redact-secret/issues/597) (DS6a). Each rule
> below states current behavior in the present tense and links the ADR
> (`docs/decisions/`) that decided it. An ADR records why and when; this file
> records what is true now. Per
> [`decision-decide-artifact-taxonomy-spec-routing-and-evidence-placement`](../decisions/2026-09-22-decide-artifact-taxonomy-spec-routing-and-evidence-placement.md),
> a decision that applies an existing policy to one more provider family or
> one more instance is a row here plus its supporting evidence, not a new
> ADR.

## Rules

The contextual-exclusion rules below all route to one representative ADR;
each row names the folded `decision_id` (preserved in that ADR's `aliases:`
field) whose permalinked full record holds the rule's original rationale.

| Rule | Governing ADR |
| --- | --- |
| A value is excluded as a non-secret reference only when the *whole* (quote-stripped) value satisfies a reference shape; a value that only starts with a marker, or embeds a reference pair inside a larger string, stays detected. `${...}`, `$VAR`, `process.env.*`, `import.meta.env.*`, and `<...>` are the only prefix-anchored exceptions. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) |
| A value fully delimited by `{{` and `}}` (Jinja, Helm, Salt, Go templates) is excluded as a template reference. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) |
| A contextual assignment's value never crosses a line terminator: the whitespace run *after* the `=`/`:` operator skips horizontal whitespace only (`is_horizontal_js_whitespace`), so a key with no same-line value reports nothing and a nested key on the next line is matched on its own. The run *before* the operator may still cross a line terminator. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-contextual-assignment-stops-at-the-line`) |
| Placeholder vocabulary is matched on ASCII-alphanumeric token boundaries by the shared `matches_placeholder_vocabulary` (`detectors/text.rs`): a value is excluded when its tokens concatenate to exactly one listed word, or every token is a listed word (a smaller digit-suffix list also tolerates a trailing digit run). `password`/`secret` are never digit-suffix tolerant, and a listed word embedded inside a larger alphanumeric run is never split out. `generic-token`, `connection-string`, and `bearer-token` each keep a local word list. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-match-placeholder-words-on-token-boundaries`) |
| An unquoted value that is a source-code expression is excluded when it starts with a listed reference root (`settings.`, `config.`, `cfg.`, `options.`, `self.`, `this.`, `var.`, `local.`, `data.`), is a dotted `lower_snake_case` chain containing an underscore, carries `Identifier<` / `Identifier[` syntax, or ends in an unmatched `(`/`[`. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-unquoted-source-code-expressions-as-contextual-values`) |
| A value that is an identifier chain carrying a balanced `(...)` argument group end to end is excluded as a call expression; an *unquoted* value whose chain opens a bracket on an identifier and never closes it is excluded as a truncated call. A quoted unbalanced value and a value with characters after its group stay detected. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-closed-call-code-expressions-as-contextual-values`) |
| A value satisfying one of seven secret-manager grammars in full is excluded: `op://<vault>/<item>/<field>`, `os.environ/<VAR>`, `projects/<id>/secrets/<name>(/versions/<v>)?`, `ref+<backend>://<path>#<key>`, `vault:<path>#<key>(#<version>)?`, `arn:aws(-cn\|-us-gov):secretsmanager:<region>:<12 digits>:secret:<name>`, and `@Microsoft.KeyVault(SecretUri=...\|VaultName=...;SecretName=...)`. A bare scheme prefix is never enough. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-secret-manager-references`) |
| An Azure Key Vault `SecretUri=` reference accepts any FQDN-shaped HTTPS host (two or more DNS labels, at most 255 bytes), not only `.vault.azure.net`; a single-label, empty, or non-DNS-charset host stays detected. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-bound-azure-keyvault-secreturi-host-by-shape`) |
| A value fully delimited by `$(...)`, `$[...]`, `#{...}`, `{env:...}`/`{file:...}`, or backticks is excluded. An unquoted value opening with one of these is scanned to its balanced close (nesting and escaped backticks honored) before the generic boundary scan; an unterminated opener falls back to the generic scan. A value opening `{env:`/`{file:` is exempt from the flow-mapping guard so an embedded one stays reported. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-interpolation-command-substitution-references`) |
| `%IDENTIFIER%` (cmd.exe environment expansion) and `:IDENTIFIER` (SQL named bind) are excluded only when the delimited content is identifier-shaped. Positional binds (`$1`, `?`), `@identifier`, and Octopus `#{Name}#` are not excluded. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-windows-env-and-sql-bind-parameter-references`) |
| A raw `"`/`'` is an assignment-prefix boundary and a valid trailing boundary after a quoted value's close, so a nested assignment inside an enclosing quote with no separator (`value="api_key="TOKEN""`) is detected at its inner range. Every value-content exclusion still applies to the nested value. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-detect-nested-assignments-with-no-separator-inside-a-quote`) |
| `connection-string`'s password check shares `generic-token`'s reference predicates from `super::text`: `$IDENTIFIER` (including `$env:VAR`), `$(...)`, `{{...}}`, `#{...}`, `{env:...}`/`{file:...}`, and `%IDENTIFIER%` are excluded; its own `${...}` check keeps requiring a closing `}`. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-share-non-secret-reference-exclusions-with-connection-string`) |
| `bearer-token` excludes repeated-character filler (one character repeated three or more times) and whole-value placeholder vocabulary, judged before any trailing `=` padding, so `Bearer`, `Basic`, and `Token` agree on a masked or placeholder value. Compound placeholders mixing an unlisted word (`EXAMPLE_TOKEN_VALUE`) stay detected. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-exclude-filler-and-placeholder-bearer-values`) |
| `heroku-api-key-legacy` has an incremental retention hint for its two documented multi-line layouts only: a Heroku `.netrc` `machine` line (plus at most two `login`/`account` lines) is held open until its `password` line, and a `heroku auth:token` command line until the next line. The hint reads back exactly the window the detector reads, so whole-input and incremental results agree; a session without the detector (`common`) never holds a unit for it. Issue #743 applies the existing retention-hint mechanism to one more detector. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-connection-string-and-jwt-need-no-retention-hint`) |
| `connection-string` and `jwt` have no incremental retention hint: detection runs only on closed lines and neither value grammar can span a line terminator. Adding a multi-line value form to either detector reopens this rule. | [Exclude a value fully delimited by `{{` and `}}` as a template reference](../decisions/2026-09-15-exclude-fully-delimited-template-references.md) (folded: `decision-connection-string-and-jwt-need-no-retention-hint`) |
| A high-signal contextual name (for example `password =`, `api_key =`) still warns unconditionally, even though it costs some prose false positives. | [Warn unconditionally on high-signal contextual-name assignments despite prose false positives](../decisions/2026-09-20-warn-unconditionally-on-high-signal-contextual-names.md) |
